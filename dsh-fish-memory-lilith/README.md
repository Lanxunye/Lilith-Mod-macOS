# 莉莉丝的长期记忆

`1.2.6-lilith.3`，适配 Yuuyuko-uu/dsh-fish-memory 1.2.6，固定提交及11个原始文件标识见 UPSTREAM.json，MIT。中文词典和词频的来源声明随包保留。

复用上游实际召回、分词、稀有词证据门槛、时间相关性、重要度与半衰期算法。upstream/index.js 只追加少量内部导出；不运行原版依赖网页版的 apply、设置网页、文件扫描、自动更新和 remember 工具。

莉莉丝原生SDK适配：

- 只处理可信宿主签名的本轮桌面/绑定主人私聊，跨这两个渠道共用 lilith-owner。群聊、辅助判断、普通DSH profile不参与。
- 当前聊天模型在原有JSON回复里安静选择稳定事实或重要事件，给出本轮主人原话证据、检索词与重要度。通过 agent/turn-stopping 记账，**没有额外记忆模型调用、向量库或外部记忆服务**。这是本项目替代上游 remember 工具的适配；不放宽原有任意工具的确认规则。
- 存的是已核实的原话，模型概述不作为事实；内部思考、莉莉丝猜测、网页和工具结果不当成主人证据。每条带来源及保存时间；时间是说这句话的时间，不擅自认定其中事件的发生时间。
- 事件默认30天半衰期，重要度越高淡得越慢；稳定事实不随时间衰减。主人再次明确提到同一件事才强化，每天至多一次；单纯被检索不会越看越强。
- 默认一天最多8条新增、每次至多6条/800字，稳定事实至多2条。同一事实键的明确新表述可以在配额满时更新，旧版本保留并停止召回，避免把旧偏好说成现在的事实。
- Companion原聊天档案保留。有原话出处的旧事实与用户摘要摘录一次性迁入；无来源的旧玩家文件不编造出处，保留原文件供查看。新插件启用后不再并行灌入旧的全部事实与摘要，关闭后也不会偷偷回落到旧召回。
- 通过现有控制台“莉莉丝的长期记忆”查看内容、鲜活度、召回依据并开关或调整半衰期/配额。`GET/PATCH /v1/dsh/memory` 沿用本机认证。既有“忘记玩家”清除派生长期记忆并阻止旧迁移复活；原始聊天档案和当前会话仍按现有产品规则保留。

数据位于独立 DSH_HOME/fish-memory，目录0700、数据与配置0600。状态损坏时不以空库覆盖原文件；该轮召回失败不会替换正常回复。SDK初始化必须等待 lilithMemoryReady。

先运行 `node scripts/build-dsh-memory.cjs` 同步共享存储模块，再运行包内 `node --test test.mjs`。Companion主测试包含迁移与渠道边界检查。正式部署前另使用隔离原生DSH做实际保存、换渠道召回和关闭后的验证；不向真实QQ发送测试消息。

上游报告的43%→91%是作者自己样本的结果，本适配没有把它当作莉莉丝的实测准确率或保证。查询日期表示“当时说过”，不代表情况至今未变；是否说得自然仍需真实对话验收。

主动搭话联动：本次版本增加签名 `LILITH_PROACTIVE_V1` 来源识别。自身发起时，情绪只判断莉莉丝自身可见表达；记忆可召回但不写入或强化主人事实。既有数据格式、原作风格与日常主人输入流程保持。

分条回复：一轮只读一次完整 messages 的实际说话内容；情绪整轮判断一次，记忆仅捕获该轮主人原话，不按气泡重复处理。
