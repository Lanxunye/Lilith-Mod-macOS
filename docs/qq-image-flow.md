# QQ 图片读取链路

2026-10-28 修复：私聊原图读取使用的 6 MiB 限额同时充当了模型输入限额，导致约 9.4 MB、8064×6048 的照片在取图阶段被拒绝。错误为 `qq_public_response_too_large`，并非视觉模型已失效。该图实际下载约需 8～11 秒，原来的 8 秒下载超时也可能中断正常取图。

当前流程：绑定会话校验 → OneBot `get_msg`／`get_image` → 受限 CDN 或已批准的本机缓存 → 大图副本处理 → 视觉模型。

- 原图读取最多 20 MiB，图片 CDN 下载超时 30 秒；保留既有域名、公共地址、重定向及本机缓存目录检查。
- 6 MiB 内的图片原样传递。较大的 PNG、JPEG、GIF、WebP 在本机临时目录处理，使用 macOS 自带的 `sips` 缩放并生成 JPEG 副本，提交模型的图片仍不超过 6 MiB。
- 大图处理前检查尺寸，最多 8000 万像素、单边 32768 像素；优先最长边 4096、JPEG 质量 85，必要时降到 3072、质量 75。处理有超时，临时文件最终清理，原文件不覆盖。
- 视觉识别与表情收集使用相同的处理副本，避免存入无法再次发送的超大表情文件。较大动画图处理为静态图片，不是视频或逐帧理解。

使用实际失败的绑定私聊图片，已完成 OneBot 只读取图、完整 CDN 下载、本机处理及真实视觉接口调用：9,404,682 字节原图处理为 3,197,728 字节 JPEG，返回 `recognized` 和有效描述；原文件哈希不变。没有生成生产聊天轮次，也没有发送真实 QQ 消息。

修改仅涉及 `qq-capabilities.js` 与新增 `qq-image.js`。视觉模型、凭据、人格、语音和 QQ 开关均不更换。此修复不改变既有私聊引用功能的单层文字引用范围。

可运行 `node companion/test/qq-image.js` 验证真实本机图像处理与模拟取图链路；常规 QQ 视觉、媒体、表情收集和成图检查回归测试也已通过。真实私聊链接和原图副本仅保存在被忽略的本机诊断目录，不随源码发布。

正式安装后的原图复测再次返回 `recognized`；该次完整下载耗时约 10.8 秒，视觉请求约 14.6 秒。常驻服务的实际视觉探针返回成功，状态为 `verified_this_run`，错误状态已清除。
