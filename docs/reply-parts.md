# 一次生成、自主分条、逐条发送

模型在一轮 JSON 中输出 `messages: [{text, emotion, animation}, ...]`，自行决定语义分界；`text` 为兼容旧入口的合并文本。正常情况下沿用模型自行规划的语义边界，也没有新增每轮三条之类的硬上限；现有整轮字数限制仍适用。旧模型只返回 text 时照常显示一条。

宿主规范化整轮内容后，第一条随请求返回，其余保存在 SQLite `reply_batches`。本地计时器按上一条长度等待约 1.8–8 秒，再提交下一条；不为分条再次调用模型。聊天主档案每条内容只记一次，不额外保存一份重复的合并回复。尚在队列中的文字不作为已发出历史。收到同一会话的新消息会取消剩余本地内容及未提交网络的 QQ 分条；生成期间收到新消息也不会在生成结束后又排出旧尾句。重复请求沿用既有结果，不重新生成或打断同一轮。

桌面即时响应显示第一条，原子投影传递后续分条的文字、情绪及阅读时长。Unity 主线程逐条展示，落后时也不在一帧闪过多个气泡。网页沿用共享历史轮询。桌面与绑定主人 QQ 私聊共享该内容；群聊仍隔离上下文和身份。

QQ 每条单独排队并保存回执，遵守既有间隔、每分钟上限和所有群合计每天100条。后一条必须等前一条回执明确成功；未知回执沿用暂停机制，不补发已确认内容。新消息、重启或取消会终止未完成内容，不在恢复后续说旧话。网络已经提交的消息无法撤回，桌面提交和 QQ 成功送达也不保证同时发生。

表情维持独立 image 消息且不带引用；若本轮有分条文字，先发送文字，最后单独发表情。私聊表情频率和交流状态按整轮计数，不因多个气泡增加亲密度或加速表情额度。撤销表情权限或收到新消息会取消尚未发送的图片。

情绪插件 0.7.0-lilith.4 与记忆插件 1.2.6-lilith.3 识别完整 messages。情绪仍在整轮生成结束时判断一次；记忆只捕获该轮有来源的主人原话一次。部分内容后来因打断未发送，仍属于莉莉丝这轮已生成的自身表达，可能已参与情绪判断；不会因此伪造主人新陈述。已验收的原作风格、伴侣、适度吃醋及傲娇规则保留。

验证入口：Companion 的 `test/reply-parts.js`、`test/reply-parts-delivery.js`；桌面 `tests/shared-chat-bridge`；隔离原生 DSH `scripts/verify-dsh-parts.cjs`。真实 QQ 不注入测试消息。部署脚本会备份正式文件及数据快照，更新独立 profile 和桌面 DLL，并重启原来正在运行的桌宠。

## 漏结构时的兜底修复

2026-10-26核对正式记录发现，最近五轮返回纯文本而没有 messages；原兜底直接把整段当一条，发送队列本身已有成功分条记录。现在优先保留有效模型分条，并兼容 messages 字符串数组；缺失或空分条时，对规范化后的纯文本按完整句和明确行边界补分条。引号、括号、代码块、行内代码、链接、数字小数及Markdown表格保持整体，一句短话仍可单发。兜底保持原规范化全文不变，不额外调用模型，不截取或重复补出的文字。

DSH每轮末尾增加简短格式提醒，减少被历史纯文本带偏；原始已提交聊天和记忆不重写。API结果/批次记录的parts_source或source可区分model与local_fallback；只读鉴权状态入口为 GET /v1/dsh/reply-parts。错误和操作确认说明保持整体。

新增回归覆盖最近五条实际回复的只读回放（五条均补成两条，内容保留）、隔离桌面与假QQ逐条投递、打断及整轮计数；完整51组回归通过。没有向真实QQ注入测试消息。

### 2026-10-26 群聊单条多句恢复

正式群聊最近的回复存在另一种退化：模型仍输出合法JSON及messages，但把两句回复装进同一个条目。此前有格式的单条计划优先级高于本地恢复，因此未触发原来的纯文本兜底。发送队列并非完全失效，既有多条计划有发送回执。

现在在normalizeResponse中传入可信渠道：qq_group且标准化后仅一个条目时，再使用同一保守句段解析器；出现多个完整句段便创建local_group_fallback计划，继承该条目的情绪、动画和合法语音参数。已有多条计划、真正的一句话、引号内句子、代码和链接仍按原边界处理。私聊的模型单条计划语义保持，原来的缺格式恢复继续有效。原生DSH与兼容提供方都传入渠道，不增加生成或修复模型调用。

补分条走现有持久化队列，首条及尾条分别发送；新同群输入、群聊关闭、少打扰规则、未知回执及物理发送额度仍有效。群间互不取消。未向真实QQ发送验收消息，也未补发历史尾条。
