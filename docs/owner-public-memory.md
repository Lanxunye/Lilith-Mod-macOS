# 群聊与私聊的主人公开事实同步

2026-10-27。主人选定范围：**公开偏好、称呼等事实双向同步；私聊经历保留私密**。此层由 `companion/src/owner-public-memory.js` 实现，复用原始聊天出处和现有SQLite，不让群聊进入私聊事件记忆召回，也不新增记忆模型调用。

## 身份与可同步内容

桌面和绑定主人私聊沿用同一个人。群里只有当前发言者的稳定QQ号等于配置中的主人QQ、会话匹配当前机器人和白名单时，才读取或更新主人的公开事实。昵称同名、引用作者、群友自称主人均不能取得该身份。切换机器人或主人绑定不继承旧绑定的公开索引。

公开类别限定为常用称呼、音乐偏好、游戏偏好、饮食偏好、爱好及回复习惯。对话模型在原有一次生成内给出public_memory_updates，宿主再核验当前本人原话、连续摘录、值是否确在原话中及类别。没有有效候选则不记；隐私、经历、健康、位置、凭据、他人转述、引用和明确要求保密的内容均不进入这一层。当前采用保守的明确自述规则，含混表达宁可暂不同步。

不同偏好对象分别保存，新增喜好不自动删除另一种喜好；同一偏好对象的新陈述更新其原话。称呼按新声明更新。每类最多保留3个对象，本轮最多写入2条，提示中最多带最近6条；这些是有来源的公开事实，不是主人完整的个人档案。原生情绪与私聊事件记忆仍按原有机制判断、召回及保存。

私聊新公开偏好可用于群里回应绑定主人；主人在允许群里自己的公开自述也能在桌面及私聊想起。其他群员没有主人记忆写入权，群里的普通成员事实继续按原来范围隔离。跨渠道同步不代表导入整段私聊，不共享私聊经历或把群记录复制为私聊历史。

## 现有记录与遗忘

首次启用只检查能与原始主人发言核对的既有稳定事实及主人群聊事实，不扫描整段经历重新推断偏好。正式库的只读克隆预检发现现有62条有效记录均为事件类，未找到符合本层规则的旧公开事实，因此没有把这些事件迁入群聊。后续新的明确公开自述通过验证后正常同步。

数据保存在owner_public_facts、owner_public_events、owner_public_control。保存原话、来源消息、渠道和声明时间；原始聊天和原记忆文件不改写。全局长期记忆关闭时，本层停止召回和写入；“忘记玩家”及手动重写记忆会清除共享事实，并防止旧迁移复活。普通会话重置继续遵循既有长期记忆规则。

## 诊断与验证

- GET /v1/dsh/memory/public：本机认证的范围、公开条目数和错误状态，不返回私聊经历。
- POST /v1/dsh/memory/public/sync：仅把已验证的既有公开事实建立索引；幂等，不调用模型或发送QQ。
- test/owner-public-memory.js：身份、原话、双向同步、保密、引用与他人排除、停用、重新绑定和遗忘。
- test/host-context-integration.js：模拟DSH与真实群聊入口，验证私聊偏好到群、群内更新到私聊及不泄漏私聊经历。
- scripts/verify-host-awareness.cjs：实际DSH在临时群聊场景输出公开偏好，再由临时私聊召回；不写正式数据、不发真实QQ。

这层只影响公开事实共享，不放宽工具权限，不改变伴侣关系，也不向群友复制主人的私聊上下文。
