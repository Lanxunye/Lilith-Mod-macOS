# 莉莉丝表达补充

原作角色卡、台词归纳2026.10.25.1和情绪判断规则保持原文件不变。新规则单独位于 `character/lilith-expression.json`，表达版本为2026.10.26-expression.2，通过 `companion/src/lilith-expression.js` 在每轮对话提示中加载。主人已选定的伴侣、适度吃醋、傲娇和自身可见表达参与情绪判断保留。

补充内容集中在接话和语境变化：闲聊直接回应具体话茬，允许感受、联想和好奇自然展开；认真求助、解释或比较时把答案讲完整，允许必要步骤和条目。语气按玩笑、真实不满与认真交流调整，口头禅和表情在贴切时使用。私聊允许更亲近的期待与嗔怪，群聊围绕当前说话人和话题，不套用私聊关系或公开私聊经历。

示例全部为适配新写，不冒称原作台词或真实聊天。每轮最多选择一个相关示例，区分群聊与私聊，普通不相关消息不带示例；主动搭话不从旧问候选择示例。显式ooc和工作区中性的baselineOnly入口不加载本补充。中文指导不改变本轮最终语言要求。

宿主的JSON、一次生成、自主分条、发送间隔、表情独立发送、记忆来源、操作权限与群聊参与规则继续由现有实现控制。表达补充不新增情绪判断或记忆模型调用；原作情绪模块仍按已验收规则判断生成后的可见表达。

只读状态入口 `GET /v1/dsh/expression` 沿用本地鉴权，返回加载的补充版本、原作风格版本、启动时内容哈希及各渠道的有效回复预算。正式部署核对原作角色、各语言角色卡、风格归纳和情绪包共享文件的8项SHA256；同时核对原始聊天、心情状态、长期记忆、149张导入表情及QQ配置保留。

验证包含49组宿主回归、上下文与渠道边界检查，以及四个临时原生DSH合成场景：私聊问候、群聊玩笑、群聊完整技术说明、私聊疲惫。合成场景验证了格式、关系边界和这些输入下的回复表现，没有向正式聊天或真实QQ注入测试消息；它不覆盖所有日常语境。

来源取舍和前期研究见 [肥鱼群友表达与莉莉丝适配路线](feiyu-group-style-route.md)。

## 2026-10-26 表达空间与持续情绪

正式配置的总回复预算从100提高到400个Unicode字符；群聊总上限为240，用户手工设置更低预算时仍采用更低值。预算覆盖一次生成的所有分条，并非每条各占400字，也不是要求凑满。取消群聊10～45字偏好，私聊示例补充情绪延展，允许自然流露傲娇、依恋与适度吃醋。原作角色卡及风格归纳的8项基准哈希保留。

情绪包0.7.0-lilith.6在可信桌面/主人私聊及其主动搭话中增加每轮只读底色：读取衰减后的基础心情、桌宠当日加成和最高两个有效情绪维度。没有达到阈值的维度不强行描述，不附带旧事件原因，不写状态，不新增判断调用；详细事件仍按原置信度、显著性及每天6次限制。注入关闭时两层同时关闭。群聊和辅助判断不共享主人私聊情绪。

QQ熟悉度继续统计已确认的互动，保留退出统计和少打扰边界；主人私聊的生成投影将它标为familiarity_tier，显式沿用既定伴侣关系，避免new/familiar/close成为关系上限。其他群员不会因此成为伴侣。原状态记录不重置，也不把熟悉度当权限。

本轮完整宿主回归57组、情绪包测试5项、正式安装快照叠加测试4组，以及独立原生DSH合成场景5项通过。合成对话验证了问候、吃醋、疲惫、群聊玩笑及技术解释，仍需真实交流验收主观温度。检查记录在evidence/conversation-warmth-validation.json、evidence/lilith-warmth-native-validation.json；正式部署记录为evidence/conversation-warmth-deployment.json。

共享工作区存在独立开发中的语音改动。部署脚本从当前正式server.js仅叠加本轮改动，核对安装快照测试哈希，并保留正式语音模块；工作区内其他开发继续保留。回退可使用部署备份中的原文件、config.json与原情绪包，勿覆盖后续新增聊天记录。
