# 表情选图：先贴切，再多样

2026-10-27，策略版本 `2026.10.27.1`。

## 本轮核对

图库中149张导入表情仍启用，加上私人及群聊缓存共169条文件记录；逐文件检查均可读，导入图哈希无异常。发送回执表明图片链路在工作，部分选中的图片因新消息、频率或取消规则没有继续发送，这些约束保留。

重复与错配主要发生在选图阶段：旧候选每次按关键词、来源与创建时间固定取前20张；没有候选曝光轮换或近期已发送统计。私聊还在正常回复生成之前选图，看不到莉莉丝这轮真正要说的话。已核对的一次睡前语境选中了实际表现为连续惊讶的GIF，图片描述本身没有错。

## 当前流程

私聊先按原来的一次生成完成对白及全部分条，再使用原有的一次选图调用。选图输入带完整待发对白、主人当前消息、近期语境和候选使用情况；不增加第二轮对白，也不增加选图模型调用次数。

本地先识别睡前、晚安、哄睡及噩梦后安抚等表达。睡前候选必须能表达安静、困倦、温柔或安心，排除惊恐、惊讶、亢奋、哭泣、打闹和明显不相干的主题。库内手工释义校正与股票、游戏等特殊主题限制继续生效。候选为空或模型没有合适选择时不发图，不随机替换一张。

通过语义筛选后，以相关程度分层，在相近候选中优先近期未发、较少发送或尚未向模型展示的图片。最近两次实际发送会降低同等级候选的优先级；明确要求重发时可找回仍符合语境的上一张。来源与动图偏好只作为后面的轻微排序因素，避免固定由同一批动图长期占满候选。

群聊仍使用原来的参与/选图调用，候选也经过语境筛选与轮换。群聊输入按字段限制长度后再序列化，避免直接截断整个JSON而丢失末尾候选。

## 使用记录与发送保护

`qq_sticker_exposure`只记录实际送给选图模型的候选曝光；普通候选预览不记账。实际使用次数仅从当前通道、目标、机器人匹配的成功图片回执计算，文字、未发出的选择、未知回执及生图不算表情已发送。群间与主人私聊不共用这份使用统计。

`qq_sticker_selection_audit`只保留最多500项范围、意图、候选数量、选中哈希和结果，不保存选图提示或聊天原文。统计和审计不增加熟悉度，也不放宽图片权限。

选图期间若本地分条计时器已排出尾条，会同步更新根消息及现有尾条的图片元数据；后续尾条继承根记录。若收到新输入、功能被关闭或原批次失效，旧选图不会继续附到回复上。表情仍排在文字之后，用独立、不带引用的图片消息发送；每三轮频率、队列间隔、撤销及未知回执暂停保持。

## 验证范围

- `test/sticker-selection.js`：同等相关候选覆盖、曝光持久化、近期回避、指定重发、语境与范围隔离。
- `test/sticker-post-reply.js`：完整分条先生成、后选图；选图期间尾条排队、文字后独立图片和新输入取消。
- `scripts/verify-sticker-selection.cjs`：只读克隆正式数据，回放睡前错配。同条件8轮候选并集由20张扩大到114张；这是候选覆盖，不是承诺实际发送114种。
- `scripts/verify-sticker-selector-native.cjs`：实际DSH在临时会话使用公开图库及虚构语境，验证睡前、哄睡、玩笑和庆祝选图；不读取私人聊天、不发真实QQ。

这些检查降低已发现的错配与重复，不能保证模型对所有隐含语义都判断准确。新的具体误用可继续按实际图片内容校正；不会为了提高多样性牺牲贴切程度。
