# DSH 聊天与操作确认修复（2026-10-26）

版本：0.3.4-macos.dev10.1。

普通聊天中曾出现 `Placeholder no-op check` / `bash true` 的多余工具调用。执行守卫正确阻止了未确认执行，但聊天服务把会话中所有未过期审批都用于替换后续回复，导致与任务无关的聊天也反复显示旧确认口令。

本次修复：

- 工作区规则明确要求闲聊、情绪安慰和角色互动直接回答，不为自检、占位或试探权限调用工具。模型收到 `LILITH_NOOP_TOOL_REJECTED` 后应回到当前聊天。
- 宿主直接拒绝 bash 的空命令及完整命令恰好为 `true` 或 `:` 的调用，不执行、不创建审批。含分号、重定向或其他内容的命令不按空操作处理，继续执行原审批规则。这不是 shell 安全解析器，也不会自动放行任何 shell 命令。
- 每次聊天生成使用独立的宿主轮次标记。只有本轮向执行守卫实际提交的待确认操作，才可覆盖本轮回复；历史待确认项仍可在控制台查看和处理，但不强制替换普通聊天。
- 明确再次请求同一操作仍会提示确认；准确确认后只允许原参数执行一次。群聊无工具权限、受保护路径、凭据隔离和危险操作审批维持原规则。

回归覆盖：旧审批下继续聊天、空占位调用无审批、复合命令仍需审批、同一操作重新申请、错误确认拒绝、准确确认单次消费，以及现有桌面与 QQ 收发测试。单元测试不能保证模型永远不会提出多余的真实工具请求；执行守卫继续兜底。

部署仅需重启本地 Companion 服务，不涉及游戏 DLL 或 DSH 桌面程序更新。正式部署的文件哈希、备份和状态检查结果见 `evidence/DSH审批提醒修复-20261026.json`。
