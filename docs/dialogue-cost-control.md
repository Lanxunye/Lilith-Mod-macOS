# 对话成本控制（2026-10-30）

莉莉丝使用 DSH 原生认证，保持原作人设、情绪、长期记忆以及桌面／QQ／DSH 面板共享的正式聊天记录。本次调整不更换聊天提供商，不修改普通 DSH 桌面配置，也不删除旧会话档案。

## 玩家需要做什么

这些节省设置默认启用，不需要更换人设或额外安装插件。群聊历史最多 5 条，少量相关成员记忆；短判断关闭思考，绘图、语音等可选服务保留自己的开关。

打开控制台，查看“DSH 聊天与用量”区域。未缓存输入、缓存输入和输出分别计量，不能将 token 总数直接按一个价格计算；独立服务费用尚未全部纳入。更新后通过 Mod 启动入口进入游戏，若后台显示旧版本，使用安装包内的“重启聊天后台.command”。

## 当前模式：DSH 纯聊天

主人进一步要求关闭所有 DSH 工具。桌面、QQ 私聊、群聊与 DSH 面板的莉莉丝聊天入口默认使用纯聊天模式，关闭全部内置操作工具和 MCP 客户端，包含文件读取／写入／删除、终端、代码、子代理、工作流及插件管理。不再显示工具执行确认，不会执行旧聊天中的操作请求。执行守卫对意外注册的工具仍然一律拒绝；真实模型请求应携带零个工具定义。

完整的既有人设通过可信宿主的每轮聊天规则提供，SDK 固定前缀只保留身份与当前模式，避免两次注入整份人格资料。没有修改角色设定文件。情绪、记忆与共享记录保持原有逻辑；宿主已实现的绘图、表情、识图、语音及联网仍受其原有开关和预算控制，它们不向 DSH 聊天模型暴露操作工具。

之前的逐次确认实现保留为隔离的兼容测试路径；正式实例不会因模型输出、旧确认短语或聊天输入而开启工具。普通 DSH 桌面自身的配置不受影响。

## REA 禁用

莉莉丝专用 profile 不再从桌面迁移 REA MCP。对已经存在的 REA 客户端，在最后加载的 overlay 中按实例 ID 设置 `disabled: true`，停止其子进程并避免注册工具定义。仅在执行阶段拒绝工具，不能减少工具定义的输入开销。

`/v1/dsh` 的 `rea_disabled`、`tools_disabled`、`chat_only` 与 `mcp_count` 可查看配置状态；真实请求头与进程树检查才是运行验证。情绪、记忆等受信插件保持原有装载规则。Purge 会注册操作工具，纯聊天模式暂停其装载，保留本体与备份；正式聊天模型无法调用工具。

## 聊天与辅助判断

- 普通聊天每轮使用新的底层 SDK 会话，以正式交付记录中的最近至多 24 条消息、总计至多约 16,000 字符的近期历史，加上原有人设、当前上下文和相关长期记忆进行回复。历史预算不包含人设、工具说明和本轮输入，不等于整次请求的硬 token 上限。
- **群聊单独限制为最近最多 5 条历史**：将同群观察到的消息和已提交回复按时间合并、去重，只向模型传一份历史，最多 4,000 字符。历史中保留说话人稳定 ID、简短昵称、正文及必要引用；去掉每条旧消息重复携带的生成图片列表、主动机会等快照。当前消息和本轮直接引用不受历史条数限制，不改动原始记录。
- **群聊记忆精简**：每轮只带当前说话人、引用对象及明确提及成员中相关的最多 4 条稳定事实，每个成员最多 2 条，每条值最多 80 字符。模型每轮最多新存 2 条当前说话人明确表达的长期事实，不记录临时情绪、玩笑或他人引用。旧事实仍保存在数据库中，私聊的长期记忆策略不变。绑定主人主动选择可公开的跨渠道偏好作为独立的共享事实池，在群内另限最多 2 条、每条 80 字符，只向已核验的绑定主人提供；不公开其他私聊经历。
- 群聊不再运行额外的自动档案摘要模型，也不向聊天注入旧的长篇档案摘录。选择性接话判断只参考最多 5 条近期消息（含最多 1 条自身发言），成员记忆最多 4 条；当前消息单独提供。群聊的话题状态、身份隔离和引用核验继续生效。
- 正式聊天记录及记忆不清空。底层旧会话文件保留，不反复追加完整的规则／历史快照。DSH 面板通过正式事件 API 续聊，继续双向写回。
- 当前纯聊天模式不恢复操作会话，也不接受操作确认。旧的逐次授权分支只用于兼容性回归，正式实例不进入该分支。
- 接话、选表情、摘要、绘图规划和搜索规划使用独立的轻量 DSH profile，不装载 REA、MCP、情绪、记忆、工作区指令或文件／终端工具。固定无工具执行守卫仍然启用。需要身份的判断规则带入原有人设参考。
- 其他辅助任务采用 `low` 思考强度；DSH 私聊选表情与群聊接话关闭思考，使用至少 512 的输出预算，传到 SDK 初始化，避免低强度思考耗尽 256 后没有 JSON 输出，未指定时默认 1,024，最大 2,048。预算是上限，不是每次都会产生的输出量。普通聊天沿用已选模型与思考设置。

## 识图缓存

图片完成既有校验与标准化后，先计算哈希，再查识图结果。缓存按会话作用域、图片哈希和视觉配置指纹隔离，保存 30 天，最多 2,000 条。视觉地址、模型或密钥改变会使旧缓存失配；私聊缓存不向群聊共享，取图前的账号／会话核验保持有效。失败结果不缓存，人工表情释义纠正仍优先应用。缓存仅保留已有识别结果，不额外保存原图。

## 统计与故障冷却

WebUI 的 DSH 状态区域显示升级后的当日 SDK 用量，分别列出未缓存输入、缓存输入、输出与调用数。`/v1/dsh.cost_control.by_module` 提供模块明细，私有数据目录 `dsh-lilith/cost-usage.json` 保存最近 31 天的数字统计，不记录提示词、聊天、账号或密钥。

该统计目前覆盖主聊天、辅助任务和可见的 SDK 压缩事件，不覆盖插件内部直接模型调用、独立阅读进程、阿里云识图以及搜索按次费用；不能替代提供商账单。心情判断和主动行为的原有配置保留。

DSH 明确返回 `AUTH`／`QUOTA` 后，共享入口进入 5 分钟冷却，期间不再提交新的聊天与辅助模型请求。修复认证或充值后可点击“连接 DSH”清除冷却。上游已发生的内部重试不属于这个入口冷却所能撤回的请求。

## 验证与回滚

运行 `cd companion && npm test` 验证审批、聊天、绘图、表情、媒体隔离等回归；`node scripts/verify-cost-control.cjs` 使用临时工作区、真实 DSH 认证和合成消息验证工具定义、模型预算及 token 用量，不发送 QQ 消息，不写正式历史或记忆。

正式部署前备份变更文件和数据库；仅需重启 Companion，不需要更新游戏 DLL。回滚时恢复该次部署的全部旧代码文件，再重启 Companion；正式历史与长期记忆继续使用原数据。本机部署记录不随公开包提供。

群聊精简另有 `test/qq-group-context.js`，检查五条历史、去重、说话人和引用归属、成员记忆上限、取消摘要及原始档案保留。`LILITH_GROUP_NATIVE=1 node test/qq-group-context.js` 使用临时数据、真实 DSH 与模拟 QQ 传输做端到端验证，不向真实 QQ 发送消息。

## 接话判断恢复

接话判断只接受含合法 `reply`／`wait`／`skip` 动作的 JSON 对象。成功后仅清除同一模块留下的 `qq_decision_failed`；错误 JSON 保留现有 @ 回复或非 @ 跳过的兜底策略，不把无效输出标为恢复。识图和私聊选图的其他错误不会被群聊判断成功抹去。

`test/qq-decision-recovery.js` 检查无输出、无效结构、错误恢复和跨模块错误隔离。`node scripts/verify-decision-recovery.cjs` 使用真实 DSH 和合成群聊／私聊候选，在同一实例先模拟失败、再验证成功清错；检查每次请求为 `off`、零工具、零思考块、有效 JSON。没有真实 QQ 发送，也不写正式历史。本机验证记录不随公开包提供。
